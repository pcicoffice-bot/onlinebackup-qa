# מלאי המסכים — מה קיים היום ומה ההמלצה

**KEEP** = נשאר כמו שהוא · **REDESIGN** = נשאר, בנוי מחדש · **MERGE** = מתאחד עם מסך אחר · **REMOVE** = יוצא · **MISSING** = לא קיים וצריך להיות.
המסמך נכתב לפי הקוד הנוכחי. **שום דבר לא ישונה בקוד לפני האישור שלך.**

## א. התקנת תוכנת הלקוח (Setup.exe — חלון Windows)

| # | מסך היום | מה יש בו | המלצה | למה |
|---|---|---|---|---|
| S1 | ברוכים הבאים (התקנה חדשה) | כותרת, הסבר, שם המחשב, Next / Cancel | **REDESIGN** | חסר פס צד עם רשימת השלבים כמו ב-installers מוכרים, וחסר מספר הגרסה. הכפתורים צריכים מיקום קבוע: Back · Next · Cancel בתחתית |
| S1b | ברוכים הבאים (כבר מותקן) | Update / Repair / Remove | **KEEP** (עיצוב לפי S1) | תואם למקובל ("Modify / Repair / Remove") |
| S2 | הסכם רישיון | טקסט, "אני מקבל", הכפתור "Install" כבר כאן | **REDESIGN** | הכפתור "Install" מופיע כבר במסך הרישיון: המשתמש מתקין בלי לראות מה עומד לקרות. במסך הרישיון הכפתור צריך להיות Next. צריך גם בחירה ברורה "אני מקבל / אינני מקבל" והדפסה / שמירה של ההסכם |
| — | מוכן להתקנה | — | **MISSING** | מסך סיכום לפני הפעולה: לאן מותקן, לאיזה שרת יתחבר, ששירות Windows יותקן ויעלה עם המחשב. רק כאן מופיע הכפתור "Install" |
| S3 | מתקין… | פס תנועה (לא אחוזים), רשימת פעולות | **REDESIGN** | צריך התקדמות אמיתית לפי שלבים (קבצים → שירות → קיצורי דרך → בדיקה), ו-Cancel שמבטל ומחזיר את המצב הקודם |
| S4 | סיום | הצלחה / כישלון / הוסר, "פתח עכשיו" | **KEEP** (עיצוב) | בכישלון חסרים "מה לעשות עכשיו" ופתיחת הלוג |

## ב. תוכנת הלקוח (OnlineBackup.Client.exe)

| # | מסך היום | המלצה | למה |
|---|---|---|---|
| C1 | התחברות (שרת, חשבון קיים / חדש, שפה) | **REDESIGN** → אשף "הפעלה ראשונה" בשלושה צעדים | היום הכול על מסך אחד: כתובת שרת, בחירת חשבון, שפה. משתמש חדש לא יודע מה חובה. ראו בהמשך ה-flow המוצע |
| C2 | מצב (בית): הסטים, גיבוי עכשיו, עדכון | **REDESIGN** | הדבר החשוב ביותר: "האם אני מוגן?" — כותרת אחת ירוקה, צהובה או אדומה עם המשפט "הגיבוי האחרון הצליח ב-…" או "נכשל — מה לעשות". אחריה הסטים |
| C3 | גיבוי חדש | **REDESIGN** → אשף (מה לגבות → מתי → סיכום) | היום זה טופס ארוך. בחירת תיקיות, תזמון וסיסמת הצפנה במסך אחד הם יותר מדי להחלטה אחת |
| C4 | שחזור | **REDESIGN** → אשף (מה → מאיזה תאריך → לאן → סיכום → התקדמות → תוצאה) | חסרים: אישור לפני דריסה של קבצים קיימים, ומסך תוצאה ("שוחזרו 1,204 קבצים, 0 נכשלו") |
| C5 | אבטחה | **MERGE** עם "הגדרות" | מסך עם פעולה אחת |
| C6 | עזרה | **KEEP** | |
| — | הגדרות (שפה, שרת, עדכון אוטומטי, הסרה) | **MISSING** | היום המידע הזה מפוזר בין המסכים |
| — | היסטוריה (הריצות האחרונות והלוג שלהן) | **MISSING** | הלקוח לא רואה למה גיבוי נכשל |
